# Persist Assistant Settings + Per-Session Subagent Selection

## Context

Two features from the chat page:
1. **Save current chat settings as an assistant** — model, tools, system prompt, MCP, A2A configs can be saved as a new named assistant
2. **Per-session subagent selection** — users can select which subagents to use in the current session, similar to how tools are currently toggled

## Architecture Analysis

### Current State
- `useAgent` hook manages `agent` state with model, tools, subagents, mcp, a2a, system_prompt
- `useChat` hook reads `agent` from `useAgentContext()` and sends it in the LLM request payload
- Assistant CRUD exists at `POST /assistants`, `PUT /assistants/{id}`, `DELETE /assistants/{id}`
- `AgentService` on frontend has `createAssistant()` and `updateAssistant()` methods (via agent creation form)
- `BaseToolMenu` + `ToolSelectionModal` handle tool selection from chat page
- Subagent selection exists in `agent-create-form.tsx` (agent creation) but NOT in the chat page
- Backend `Assistant` schema includes `subagents: Optional[list[dict]]`

### Feature 1: Save as Assistant

**Approach**: Add a "Save as Assistant" button/action in the chat settings area. On click:
1. Show a dialog requesting name + description
2. Collect current state from `agent`: model, tools, system_prompt, mcp, a2a, subagents, files
3. POST to `/assistants` via existing `AgentService.createAssistant()`
4. On success, set the newly created assistant as the active agent
5. Toast notification with success/error

**Files to change**:
- `frontend/src/components/nav/ChatNav.tsx` or `frontend/src/components/sections/agent-section.tsx` — add "Save as Assistant" button
- New: `frontend/src/components/dialogs/SaveAsAssistantDialog.tsx` — name/description dialog
- `frontend/src/lib/services/agentService.ts` — ensure `createAssistant` works for this use case
- `frontend/src/hooks/useAgent.ts` — add `saveCurrentAsAssistant()` method

### Feature 2: Per-Session Subagent Selection

**Approach**: Mirror the tool selection pattern. Add a subagent picker accessible from the chat page.
- Add a subagent section/button near the tool selector in `BaseToolMenu` or as a separate control
- Show available agents (from `agents` list) with toggle to add/remove as subagents
- Uses existing `addAgentToSubagents`, `removeAgentFromSubagents`, `toggleSubagent` from `useAgent`
- Changes are session-local (stored in `agent` state), not persisted unless user saves as assistant

**Files to change**:
- `frontend/src/components/menus/BaseToolMenu.tsx` — add subagent section/tab
- New or extend: `frontend/src/components/modals/SubagentSelectionModal.tsx` — agent picker with toggles
- Possibly extend `ToolSelectionModal` to include a "Subagents" tab

## Story Breakdown

1. **Backend validation** — Ensure POST /assistants accepts all fields from chat state (already works, just verify)
2. **Save as Assistant dialog** — New dialog component with name/description inputs
3. **Save as Assistant integration** — Wire dialog to agent state + API call + navigation
4. **Subagent selection UI** — Modal/panel to select subagents from available agents
5. **Subagent selection integration** — Wire to chat page, ensure selected subagents are sent in LLM requests
6. **Docs check** — Review wiki for drift, update if needed
7. **Final verification + push**

## Risks
- Subagent selection UX needs to avoid confusion with tool selection
- Saving as assistant should handle edge cases: no model selected, no tools, duplicate names
- MCP config is stored in localStorage — needs to be included in the save
