# Fix: Schedules Not Visible in Calendar/Table Views

## Context

On the `/schedules` page, the status cards correctly show "2 Total" schedules, but both Calendar and Table views are empty. The root cause is a **data source mismatch**: status cards derive counts from `schedules[]` (schedule definitions), while Calendar/Table views render from `filteredCalendarEvents` which is derived exclusively from `executions[]` (execution history). When schedules have no recent executions, the views are empty.

## Fix: Generate Projected Events from Schedule Definitions

Merge synthetic "projected" events (from each schedule's `next_run_time`) with execution-based events so schedules always appear in Calendar/Table.

### Step 1: Add two functions to `frontend/src/lib/utils/calendar.ts`

**`mapSchedulesToProjectedEvents(schedules: Schedule[]): ScheduleEvent[]`**
- For each schedule with a `next_run_time`, create a `ScheduleEvent` with:
  - `id`: `"projected-{schedule.id}"` (prefix avoids ID collisions)
  - `start`: `new Date(schedule.next_run_time)`
  - `end`: start + 30 minutes (matches execution convention)
  - `resource.status`: `"scheduled"` (already styled as blue in `getExecutionStatusColor`)
  - `resource.execution_id`: `""` (no execution exists yet)
  - `resource.agent_id`: from `schedule.agent_id` or `schedule.task.metadata.agent_id`

**`mergeAndDeduplicateEvents(executionEvents, projectedEvents): ScheduleEvent[]`**
- Build a set of schedule_ids that have an execution within 1 hour of the projected time
- Filter out projected events that are "covered" by an execution
- Return `[...executionEvents, ...filteredProjected]`

### Step 2: Update `frontend/src/pages/schedules/index.tsx` (~10 lines)

Replace the `filteredCalendarEvents` memo (lines 232-236):

```typescript
// BEFORE:
const filteredCalendarEvents = useMemo(
  () => mapExecutionsToEvents(filteredExecutions, schedulesMap),
  [filteredExecutions, schedulesMap],
);

// AFTER:
const filteredCalendarEvents = useMemo(() => {
  const executionEvents = mapExecutionsToEvents(filteredExecutions, schedulesMap);
  const projectedEvents = mapSchedulesToProjectedEvents(filteredAndSortedSchedules);
  return mergeAndDeduplicateEvents(executionEvents, projectedEvents);
}, [filteredExecutions, schedulesMap, filteredAndSortedSchedules]);
```

Uses `filteredAndSortedSchedules` so projected events respect search/status/agent filters.

Update the import to include the two new functions.

**Optional enhancement** to `handleEventClick`: clicking a projected event opens the edit dialog (since there's no thread to navigate to).

### Step 3: Add unit tests

Create `frontend/src/lib/utils/calendar.test.ts` with tests for:
- `mapSchedulesToProjectedEvents`: empty input, correct field mapping, filters missing `next_run_time`
- `mergeAndDeduplicateEvents`: dedup within 1hr, keeps non-covered projected events, preserves all execution events
