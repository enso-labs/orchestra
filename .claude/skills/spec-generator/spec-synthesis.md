# Skill: Spec Synthesis

## Purpose
Combine all gathered context, analysis, and insights into a comprehensive, structured specification document.

## Single Responsibility
Synthesize analysis outputs into a final specification file.

## Invocation
```
skill: spec-synthesis
inputs:
  - context: object (from context-extraction)
  - changes: object (from change-detection)
  - gaps: object (from gap-analysis)
  - assumptions: object (from assumption-invalidation)
  - end_state: object (from end-state-regression)
  - signals: object (from signal-noise-filtering)
  - spec_type: string (feature|bugfix|refactor)
```

## Process

1. **Generate Spec ID**
   - Format: `SPEC-{TYPE}-{YYYYMMDD}-{SHORT_HASH}`
   - Example: `SPEC-FEATURE-20250110-a1b2c3`

2. **Assemble Sections**
   - Header with metadata
   - Problem/Feature statement
   - Context summary
   - Requirements
   - Acceptance criteria
   - Technical approach
   - Assumptions and risks
   - Open questions
   - Next steps

3. **Write to `.claude/specs/`**
   - Filename: `{spec_id}.md`
   - Create directory if needed

## Output Template

```markdown
# {SPEC_ID}: {Title}

## Metadata
- **Generated**: {timestamp}
- **Type**: {feature|bugfix|refactor}
- **Source Branch**: {branch}
- **Base Branch**: {base}
- **Status**: draft

## Summary
{One paragraph description of what this spec covers}

## Problem Statement
{What problem is being solved or what feature is being added}

## Context
### Recent Changes
{Summary from context-extraction and change-detection}

### Relevant Signals
{Key information from signal-noise-filtering}

## Requirements
### Functional Requirements
{Derived from end-state-regression}

### Non-Functional Requirements
{Performance, security, etc. if identified}

## Acceptance Criteria
{From end-state-regression acceptance_criteria}

## Technical Approach
### Components Affected
{From change-detection domains}

### Implementation Steps
{From end-state-regression critical_path}

## Assumptions
### Validated
{From assumption-invalidation validated}

### Requires Verification
{From assumption-invalidation unverified}

## Gaps and Open Questions
### Critical Gaps
{From gap-analysis critical}

### Questions for Stakeholders
{Synthesized from gaps and unverified assumptions}

## Risks
{Derived from invalidated assumptions and high-risk changes}

## Next Steps
1. {First action item}
2. {Second action item}
...

---
*Generated by spec-generator agent*
```

## Output
Creates spec file in `.claude/specs/` and returns the spec ID and path.
