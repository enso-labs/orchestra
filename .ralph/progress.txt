## Codebase Patterns
- API validation: Only one of `system_prompt` or `instructions` may be set in assistant creation/update, not both
- Integration tests: Use `pytest.skip()` pattern for DB-dependent tests when login fails (ensures CI can handle missing seeds)
- Login helper pattern: `_login()` returns auth headers, `_create_assistant()` returns assistant_id, `_get_assistant()` returns assistant dict
- LLM routes: `/api/llm/stream` returns 200 (direct) or 202 (distributed); `/api/llm/invoke` may return 500 with mocked external APIs
- File panel: `agent-browser` CSS selector `"h1 + button"` targets the create button next to page heading
- Agent browser: Login requires filling email/password textboxes then clicking Sign in; session persists across navigation
- License check: Always verify library licenses before adding — AGPL (e.g. Intro.js) is incompatible with this project
- Wiki links: Use relative paths with `.md` extension (e.g., `../assistants/agents-md.md`), not absolute slug paths — Docusaurus breaks on absolute slugs
- Wiki external URLs: Docusaurus `routeBasePath: 'docs'` means absolute URLs must include `/docs/` prefix (e.g., `https://docs.ruska.ai/docs/assistants/agents-md`)
