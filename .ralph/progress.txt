- react-hook-form fields must be explicitly synced with form.setValue() when using custom components that don't integrate directly with RHF's register/Controller

## 2026-02-16 - US-002
- **What was implemented**: Fixed model pre-population on the assistant edit page. The root cause was that ChatContext and AgentContext each instantiate their own `useModel()` hook with separate state. When `useAgent` fetched the agent and called its own `updateQueryStateModel`, it only updated the AgentContext's model state — not the ChatContext's model state that `SelectModel` reads from. The fix destructures `setModel` from `useChatContext()` in the form component and calls it in the existing useEffect that syncs agent data to the form, so SelectModel displays the agent's saved model on load.
- **Files changed**:
  - `frontend/src/components/forms/agents/agent-create-form.tsx` - Added `setModel` from `useChatContext()` and call `setModel(agent.model)` in the agent data sync useEffect
- **Learnings for future iterations:**
  - ChatContext and AgentContext each create their own `useModel()` instance — they have SEPARATE state. `updateQueryStateModel` in AgentContext does NOT update ChatContext's model.
  - SelectModel reads `model` from `useChatContext()`, so any component wanting to control what SelectModel displays must update ChatContext's model state via `setModel`.
  - When debugging state sync issues in React, always verify that the state being read and the state being written are from the SAME context/hook instance.
  - The Radix scroll area component (`data-radix-scroll-area-viewport`) needs its own `scrollTop` manipulation for browser testing — standard page scroll doesn't work.
