## Codebase Patterns
- Backend uses async SQLAlchemy with PostgreSQL (see backend/src/services/db.py for DB_URI and connection patterns)
- Schedules use APScheduler SQLAlchemyJobStore (table "schedules") — not standard SQLAlchemy models
- Schedule execution dispatch: scheduled_llm_invoke() in backend/src/services/schedule.py has two paths: distributed (TaskIQ) and in-process
- FastAPI route ordering matters: /executions/recent must come before /{job_id} or "executions" gets captured as path param
- Auth pattern: ProtectedUser dependency (see existing schedule routes for examples)
- Pydantic schemas live in backend/src/schemas/entities/
- SPA catch-all on backend serves index.html for unrecognized routes — this is why missing endpoints return HTML not 404
- Frontend expects ScheduleExecution interface: id, schedule_id, thread_id, status, scheduled_time, started_at, completed_at, error_message, metadata
- `make format` in backend runs `uvx ruff format` - run before committing
- `make test` in backend sources env from `~/.env/orchestra/.env.backend` before running pytest
