## Codebase Patterns
- Wiki is a git submodule - must run `git submodule update --init wiki` in worktrees before editing
- Wiki submodule commits must be done inside the `wiki/` directory first (create branch, commit), then commit the submodule pointer update in the main repo
- The `bd` pre-commit hook requires `BEADS_DIR=/path/to/main-repo/.beads` env var when committing from worktrees (workaround: `BEADS_DIR=/home/ryaneggz/ruska-ai/orchestra/.beads git commit ...`)
- Wiki uses Docusaurus; sidebar config is in `wiki/sidebars.ts`; typecheck with `npx tsc --noEmit` from wiki dir
- Existing broken links in wiki build (sandbox → tools/mcp) are pre-existing, not caused by new changes
- Docusaurus relative doc links must use `.md` extension (e.g., `./tutorial.md`) when source page has custom `slug`
- Run `npx tsc --project tsconfig.json --noEmit` from wiki dir (explicit `--project` flag needed)
- Docusaurus validates image references at build time — all referenced images in markdown must exist in `wiki/static/`
- `website` is also a git submodule — same init and commit workflow as `wiki`
- Frontend dev server in worktrees: `npm run dev` may fail due to `dotenv` conflicts; use `npx vite --host` directly after `npm install`
- Browser screenshots: use `agent-browser set media light` + `agent-browser set viewport 1280 800` before navigating
