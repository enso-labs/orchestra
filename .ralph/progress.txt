1. **(info)** `prepare_memory_files()` (`src/agents/__init__.py:68-115`) — Changed from 2-tuple to 3-tuple return `(files_map, memory_sources, original_content)`. All 3 callers updated correctly:
   - `src/controllers/llm.py:121` — `llm_invoke()` unpacks 3-tuple, passes `original_content` to `construct_agent()`
   - `src/utils/stream.py:209` — `stream_generator()` unpacks 3-tuple, passes to `construct_agent()`
   - `src/workers/tasks.py:238` — `_execute_agent_stream()` unpacks 3-tuple, passes to `construct_agent()`
   - `original_content` correctly captures the raw content string (line 113), not the FileData dict.

2. **(info)** `MemorySyncMiddleware` (`src/utils/middleware.py:274-315`) — Well-structured:
   - Uses `aafter_agent` hook correctly (async post-agent lifecycle)
   - `memory_sources` converted to `set` for O(1) lookup (line 294)
   - Content join with `"\n"` (line 305) matches the split used in `create_file_data`
   - Leading slash strip via `lstrip("/")` (line 310) correctly maps `/AGENTS.md` → `AGENTS.md` for MemoryRepo keys
   - Error handling: entire try/except at top level catches + logs as warning, returns `None` — never propagates

3. **(warning)** `MemorySyncMiddleware` error handling granularity (`src/utils/middleware.py:299-314`) — The try/except wraps the entire loop. If `repo.update()` fails on the first memory file, the exception is caught at the top level and **remaining files are skipped**. This is a design choice (not a bug) — the test `test_partial_failure_does_not_sync_remaining` confirms this is intentional. However, a per-file try/except would be more resilient. Consider wrapping the inner loop body for future improvement.

4. **(info)** `construct_agent()` wiring (`src/agents/__init__.py:340-400`) — Precondition check at line 371 requires all 4 conditions: `memory is not None`, `original_content is not None`, `service_context` truthy, and `service_context.user_id` truthy. MemoryRepo is created fresh with correct `user_id` and `store`. `middleware = list(middleware) + [sync_mw]` correctly creates a new list (no mutation of default arg). Existing middleware is preserved.

5. **(info)** `llm_stream` path (`src/controllers/llm.py:160-177`) — The `llm_stream` method does NOT pass `original_content` because it delegates to `stream_generator` which handles its own memory loading. No gap here.

6. **(info)** Test coverage is thorough:
   - **Unit tests** (4 files):
     - `test_memory_sync_middleware.py` — 13 tests: happy path, no-change, empty sources, missing files, multiple files, multiline content, non-memory files, error handling (no raise, logged), partial failure, return value
     - `test_prepare_memory_files.py` — 14 tests: empty cases (None/empty user, empty search, exception), populated cases (multiple, single, disabled, non-dict), original_content mapping
     - `test_construct_agent_memory_sync.py` — 6 tests: middleware added/not-added based on all preconditions, correct MemoryRepo, existing middleware preserved

   - **Integration tests** (1 file):

7. **(info)** No `.env` file reads, no `vite.config.ts` changes, no leaked secrets. The `api_key` references in the diff are existing parameter passing patterns.

8. **(info)** `MemoryRepo.update()` (`src/repos/memory_repo.py:36-56`) — The `update` method fetches existing, preserves `created_at` and non-None fields, updates `updated_at`.
