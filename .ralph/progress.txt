## Codebase Patterns
- Backend uses `deepagents` library for SubAgent support
- `construct_agent()` in `backend/src/agents/__init__.py` sets up subagents
- `astream()` called with `subgraphs=True` to get subagent messages
- `lc_agent_name` is a LangGraph-injected field on messages from subgraphs
- `handle_multi_mode()` in `backend/src/utils/stream.py` already detects `lc_agent_name` but only logs it
- `_to_dict()` uses `.model_dump()` for Pydantic models — `lc_agent_name` DOES survive as a dynamic attr
- `model_dump()` includes `lc_agent_name` when set dynamically on LangChain messages (tested with langchain_core 1.2.7)
- Both `_to_dict()` and `from_message_to_dict()` now promote `lc_agent_name` → `agent_name` for frontend consumption
- 6 pre-existing test failures in `tests/unit/tools/test_search.py::TestWebSearchTool` — unrelated to this feature
- Frontend message pipeline: useChat.ts handleMessages → StreamMessageHandler → formatMessages → ChatMessages.tsx
- Tool calls render via ToolTimeline → ToolTimelineItem
- AI responses render via MarkdownCard in ChatMessages
- TypeScript build check: `./node_modules/.bin/tsc -b` (no standalone `typecheck` npm script)
- Must run `npm install` in frontend worktree before builds (node_modules not shared across worktrees)
