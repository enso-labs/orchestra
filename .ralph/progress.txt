## Codebase Patterns
- Package lives at `packages/agent-ts/` with `type: "module"` ESM setup
- Build uses plain `tsc` with bundler moduleResolution for ESM compatibility
- `.env.example` files require `git add -f` due to parent `.gitignore` pattern matching `.env*`
- `dist/` is gitignored — build artifacts are not committed
- Use `loadConfig(customEnv)` in tests instead of mutating `process.env`
- Test files live alongside source: `src/foo.test.ts` next to `src/foo.ts`
- Logger uses `process.stderr.write()` for structured JSON — spy with `vi.spyOn(process.stderr, "write").mockReturnValue(true)` in tests
- Use `any` type for `vi.spyOn(globalThis, "fetch")` to avoid complex vitest MockInstance type issues with overloaded fetch signatures
- Backend SSE format: `data: ["eventType", payload]\n\n` — event types are `metadata`, `messages`, `values`, `error`, and `[DONE]` sentinel
- Mock fetch in tests with `new Response(readableStream, { status, headers })` — use `ReadableStream` for SSE body simulation
- Subdirectories under `src/` work fine — import with `./prompts/system.js` relative paths
- Tool registry uses module-level arrays/maps — call `_resetRegistry()` in `beforeEach` for test isolation
- `ToolDefinition.parameters` is typed as `z.ZodType` — any Zod schema works (z.object, z.string, etc.)
- Tools needing external callbacks (e.g., `human_contact.promptFn`) use `options` third arg — same DI pattern as `file_writer.outputDir`
- `registerTool` replaces existing tools with the same name — supports tool override pattern
- Middleware hooks are optional — only define the hooks your middleware needs (beforeLLM, afterLLM, beforeTool, afterTool)
- `runBeforeLLM` and `runBeforeTool` chain their outputs; `runAfterLLM` is side-effect only (no chaining)
- Cannot `vi.spyOn` ESM `node:fs/promises` exports — use real filesystem I/O in tests with temp dirs and cleanup in `afterEach`
- Mock `streamChat` with `vi.mock("./stream-client.js")` — use async generators for mock streams
- Agent loop handles tool_calls from `messages` event data: `{ id, name, args }` objects in `tool_calls[]` array
- `extractJSON()` tries: raw string, code fences, first `{...}` block — handles LLM responses wrapped in prose/markdown
- Tool results appended as `{ role: "tool", content: "[Tool: name] result" }` messages for next LLM turn
- Server tools (local: false) are filtered out of local execution — only sent in API request `tools` array
- Context trimming middleware keeps first message (system) + summary placeholder + last N messages — never loses the system prompt
- Non-JSON retry: `nonJsonRetries` counter tracks consecutive non-JSON responses; resets to 0 after any tool call turn; throws `StructuredOutputError` after `MAX_NON_JSON_RETRIES` (2)
- `singleTurn` option: sends one request and returns or throws immediately — no retry loop
- Nudge message appended as `{ role: "user" }` asking LLM to output only raw JSON matching the ResearchResult schema
- Use factory function pattern for middleware needing dependencies (e.g., `createObservabilityMiddleware(logger)`) — allows DI and per-instance state via closures
- Tool handlers receive `options` as third arg — use `options.outputDir` for config injection in tests
