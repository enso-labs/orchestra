## Codebase Patterns
- Agent construction in `backend/src/agents/__init__.py` — `construct_agent()` builds LangGraph agent with tools, subagents, model
- SubAgent support via `deepagents` library — supervisor-worker hierarchy
- Daytona sandbox in `backend/src/agents/daytona.py` — code execution environment
- Streaming via `backend/src/utils/stream.py` — SSE with `["messages", [chunk, metadata]]` format
- `subgraphs=True` enables subagent message streaming
- Existing RLM skill at `.claude/skills/rlm/SKILL.md` — Claude Code-level pattern (not platform-level)
- RLM paper: arXiv:2512.24601v2 by Alex Zhang
- RLM library: `pip install rlms` — https://github.com/alexzhang13/rlm
- RLM core: `rlm.completion(prompt, model)` replaces `llm.completion()` — REPL-based decomposition
- REPL environments: local (exec), Docker, Modal, Prime sandboxes
- RLM LMHandler: TCP socket server on localhost routes LLM calls by depth (depth=0 → root model, depth=1 → sub-model)
- RLM isolated envs use HTTP broker pattern: Flask app inside sandbox + poller thread on host
- RLM state persistence: dill serialization in isolated envs, in-memory dicts in LocalREPL
- RLM prompt parsing: ```repl``` code blocks, FINAL()/FINAL_VAR() for answers
- RLM batched queries: `llm_query_batched()` → asyncio.gather on server side
- Orchestra model middleware routes by complexity (simple/complex), not depth — different from RLM's depth routing
- `AutoEvictMiddleware` evicts tool results >40k chars to filesystem — partial analog to RLM's REPL-resident context
- deepagents SubAgents execute sequentially under supervisor — no parallel sub-LM support
- No per-request token metering in Orchestra — only heuristic `len(content)//4` for compaction
- Critical gap: RLM has no streaming, Orchestra requires SSE streaming for UX
- Frontend SSE: `streamSource.ts` (SyncStreamSource/DistributedStreamSource) → `useChat.ts` → `ChatMessages.tsx`
- Tool calls render in `ToolTimeline` → `ToolTimelineItem` (collapsible cards)
- No SubAgent hierarchical rendering in frontend yet — flat message display
- `deepagents==0.3.8`, `langgraph==1.0.7` — no `Send()` API usage in codebase
- `max_concurrency=4` in RunnableConfig but SubAgents still execute sequentially
- Only `asyncio.gather()` usage: search tool URL fetching with `Semaphore(5)`
- `rlms` not installed in backend — feature #793 is research/planning phase
- rlms v0.1.0 — `get_client(backend, backend_kwargs={...})` signature; `ModelUsageSummary` uses `total_input_tokens`/`total_output_tokens`/`total_calls`
- rlms FINAL_VAR extraction is unreliable — sometimes returns variable name instead of value
- rlms has no streaming callbacks — verbose mode logs to console only, not programmatic
- For within-context inputs, standard completion beats RLM on latency (2.5x) and cost (7.4x)
- RLM iteration context grows with each REPL cycle — dominant cost amplification factor
- Use `uv run --with "rlms>=0.1.0"` for isolated script execution without modifying backend deps
