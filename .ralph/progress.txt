## 2026-02-16 - US-001
- What was implemented: Decoupled SelectModel from ChatContext by adding optional controlled props (`value`, `onChange`, `modelsList`). When these props are provided, SelectModel uses them instead of `useChatContext()`. When not provided, it falls back to context (backward compatible).
- Files changed: `frontend/src/components/lists/SelectModel.tsx`
- **Learnings for future iterations:**
  - `useChatContext()` returns `any` type — the context is untyped, so always destructure what you need
  - React hooks must always be called (can't conditionally skip `useChatContext()`), so the pattern is: always call the hook, then use `prop ?? contextValue` to choose
  - The `onModelSelected` callback is called with no arguments — it's a notification, not a value setter
  - All 232 frontend tests pass; the `modelBadgeIntegration.test.tsx` suite specifically checks that SelectModel exists and is imported in agent-create-form

## 2026-02-16 - US-004
- What was implemented: Fixed a bug where editing a schedule with custom configuration (`inherited_from_agent: false`) would always show "Use Agent Settings" mode instead of "Custom Configuration" with the saved model. Changed `|| true` to `?? true` for `inheritFromAgent` in both `SchedulesIndexPage` and `AgentSchedulesPanel`.
- Files changed: `frontend/src/pages/schedules/index.tsx`, `frontend/src/components/panels/AgentSchedulesPanel.tsx`
- **Learnings for future iterations:**
  - CRITICAL: `false || true === true` in JavaScript! Always use `??` (nullish coalescing) instead of `||` for boolean values that can be legitimately `false`. The `||` operator treats `false`, `0`, `""` as falsy and falls through to the default.
  - The ScheduleTable and ScheduleCalendar views show **execution events**, NOT schedules. A newly created schedule without past runs won't appear in these views. The schedules are tracked by the `useSchedules` hook but only displayed via `mapExecutionsToEvents`.
  - The edit dialog is triggered by `handleEditSchedule(scheduleId)` which fetches the full schedule from `/api/schedules/:id` and sets `editingSchedule` state + `showEditDialog: true`.
  - Schedule data saved in the API: `task.model` holds the selected model, `task.metadata.inherited_from_agent` holds the boolean for inherit mode. These map directly to `initialData.customModel` and `initialData.inheritFromAgent`.
  - Verified via API that schedule save persists correctly: `model=anthropic:claude-sonnet-4-5, inherited=false` confirmed in API response.
