## 2026-02-21 - US-002 (Re-verification) + US-003
- Identified root cause of blank tool inputs on /chat streaming path:
  1. First `tool_call_chunk` creates entry with `input: ""` (empty string) → `content` resolves to "" → blank Monaco editor
  2. `in_mem_messages` diverges from React state because `setMessagesState` (not `setMessages`) is used after `formatMessages`
  3. `useMemo([selectedToolMessage])` depends on object reference, not the actual content values
- **Three-part fix applied:**
  1. `Default.tsx`: Return `null` when content is empty — prevents blank dark rectangles entirely. Editor mounts only when content is available.
  2. `Default.tsx`: Changed useMemo dependency from `[selectedToolMessage]` to `[rawInput]` where `rawInput` is derived via nullish coalescing (`??`) outside the memo. This ensures value-based (not reference-based) change detection.
  3. `useChat.ts`: After `setMessagesState(normalizedHistory)`, sync `in_mem_messages = [...normalizedHistory]` to keep the SSE mutation target in sync with React state.
- Browser verified on local dev server (localhost:5174, backed by production API):
  - 5 threads tested: Tokyo, NYC, Berlin, London (multi-tool), San Francisco
  - All Monaco editors display correctly formatted JSON content
  - Read-only confirmed on all editors
  - No blank rectangles observed
  - Multi-tool support works (2 editors in London thread)
- Files changed: `frontend/src/components/tools/Default.tsx`, `frontend/src/hooks/useChat.ts`
- Commit: `b2a8ae5e feat: [US-003] - Fix blank tool inputs on new chat page during streaming`
- **Learnings for future iterations:**
  - `in_mem_messages` is a module-level variable in `useChat.ts` — it's the mutable backing store for SSE streaming. Always keep it in sync with what React renders.
  - `StreamMessageHandler.toolCall()` mutates `in_mem_messages` in-place (push/replace). After `formatMessages()` normalizes, the module-level var must be updated to prevent the next event from operating on stale data.
  - `useMemo` with object reference deps (e.g., `[selectedToolMessage]`) CAN miss updates when the object is a shallow copy (`{ ...msg }`) but the relevant VALUE inside hasn't changed detection-wise. Prefer value-based deps for streaming data.
  - First `tool_call_chunk` from backend typically has `args: ""` (empty string). Plan for empty-initial-then-accumulating pattern in any tool display component.
  - `??` (nullish coalescing) is better than `||` for extracting tool input fields because `""` is a valid (though empty) value — `||` treats it as falsy and falls through.
