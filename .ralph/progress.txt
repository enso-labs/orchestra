## Codebase Patterns
- PostgreSQL must be running for backend tests (even unit tests) — start with `docker compose up -d postgres`
- Redis should also be running for tests — `docker compose up -d redis`
- Pre-commit hooks run format, lint, AND tests — all must pass to commit
- For testing TaskIQ tasks with lazy imports, patch at the source module (e.g., `src.services.db.get_store_db`) not at the task module — lazy imports resolve at call time
- `fork_count` is stored directly on Assistant model, not in metadata dict — follows pattern of other public agent fields (public, owner_id, published_at)
- `forked_from` is tracked via `metadata["forked_from"]` (not a top-level field) — keeps Assistant schema clean for less frequently accessed lineage data
- For cross-namespace writes, construct namespace tuple directly: `(target_user_id, self._get_store_key())` — don't rely on `self._get_namespace()` which uses `self.user_id`
- Frontend Agent type `metadata` is `Record<string, unknown>` — access `forked_from` via `(agent.metadata as Record<string, unknown>)?.forked_from`
- 2 pre-existing test failures in `test_default_system_prompt_runtime.py` — ignore these, they're unrelated to marketplace work
- Embed tokens use `type: "embed"` in JWT payload to distinguish from user auth tokens — validate this field when verifying embed JWTs
- Embed token `jti` enables per-token rate limiting keyed by `embed:{agent_id}:{jti}` in Redis
- Public assistant routes in `assistant.py` are grouped: GET /public, GET /public/{id}, POST /public/{id}/fork — then publish/unpublish section follows
- For public endpoints that don't need user context, use `AssistantService(user_id=None, store=store)` directly (no ServiceContext)
- Frontend: `getAuthToken()` checks auth without hooks; `apiClient` auto-attaches Bearer token via interceptor
- Frontend: Edit page route is `/assistant/:agentId` (singular); public agent page is `/a/:agentId`
- Assistant model validates only one of `system_prompt` or `instructions` may be set — test data must set the unused one to `None`
- `tags` is a top-level `list[str]` field on Assistant (like `fork_count`), not in metadata — keeps discovery/filtering fast
- `search_public()` fetches all public assistants then filters/sorts in Python — acceptable for current scale, may need DB-level filtering later
- GET /assistants/public uses `Literal` type hint for `sort_by` enum validation in FastAPI (not `Query(enum=...)`)
- Tags query param is comma-separated string parsed in the route, passed as `list[str]` to the service
- Tag chip input pattern: local `tags` state + `tagInput` state + `ref`, synced from agent in useEffect, Enter/comma to add, Backspace to remove last, `e.preventDefault()` to avoid form submission
- Discover tab cards navigate to `/a/{id}` (public page), My Agents cards navigate to `/assistant/{id}` (edit page)
- Tag chips use `bg-primary/10 text-primary` styling; tool badges use `bg-secondary text-secondary-foreground`
- Embed widget uses inline styles (no Tailwind/CSS) to avoid leaking styles to/from host page — keep this pattern for all embed components
- `npm run build:embed` uses `vite.embed.config.ts` (separate from main `vite.config.ts`); output goes to `frontend/dist/embed/embed.js`
- For embed chat, use `assistant.to_llm_request(input, metadata=config)` to construct LLMRequest from the Assistant model — avoids manually copying system_prompt, tools, etc.
- Embed rate limiting uses Redis INCR + EXPIRE pattern: first INCR creates key with count=1, then set TTL 86400s; subsequent INCRs just increment
- `HTTPBearer(auto_error=False)` allows optional Bearer token — returns None credentials instead of 401 when no token provided
- Trajectory namespace uses 3-tuple `(user_id, "trajectories", assistant_id)` — deeper than typical 2-tuple to partition per-assistant
- `AnnotatedTrajectory` uses `._asdict()` for serialization to store, and `{role, content}` format (not `{type, content}`)
- `get_store_db()` as async context manager is the simplest store access in background tasks (works regardless of worker state mode)
- `stream.py` ↔ `workers/tasks.py` circular import — use lazy import inside function body, not top-level
- Two streaming paths: synchronous (`stream_generator` in stream.py) and distributed (`_execute_agent_stream` in tasks.py) — both must be updated for post-stream hooks
- `store.alist_namespaces(max_depth=N)` discovers all stored namespaces — filter by tuple structure to find specific types (e.g., `ns[1] == "trajectories"`)
- APScheduler system jobs in lifespan use `replace_existing=True` + `misfire_grace_time` for robustness across restarts
